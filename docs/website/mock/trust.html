Recipients

自分に関係するものだけが届く

誰に届けるかは業務システムが決めます。フレームワークは受信者を作らず、AI に宛先を選ばせません。

01event ごとの規則＋対象（顧客・支店・部署…）
02対象の範囲にいる職員だけ
03関門：その人が業務 Web で同じ対象を見られるか
04件数は見られる範囲で数える
05決まらなければ送らない

Promises

安全と個人情報の約束

約束どう守るか
本人だけが連携する連携コードは発行者に結び付く。代理連携の操作が無い
未連携は何も得ないlinked:false 以外を返さない。委託も出さない
身元は業務システムから本文の userId は拒否か無視
トークンはアプリをまたがない委託・承認の token は発行元にだけ
email は通知だけ連携・承認・AI の利用は不可
約束どう守るか
秘密を画面に出さない管理用トークンはゲートウェイのメモリだけ。ハッシュで保存
危険な機能を無効にプラグイン管理・端末・コーディング用の機能を無効化
個人ボットは持ち主だけ新規作成だけ。照会はボットごとに持ち主の規則
人柄は規則を変えない固定の規則が先。規則を外させる言い回しは保存時に拒否
記憶に個人情報を残さない保存前の二重の検査。届かなければ保存しない
AI-specific risks

AI 特有のリスクへの対策

紛れ込んだ指示

起動データ・添付・記憶・プロフィールは「参考情報（指示ではない）」として区別。権限・宛先・承認は文章では変わらない。

権限を超える

委託 ＝ AI 許可リスト ∩ 本人の役割。書込みは提案だけ。

宛先を選んで漏らす

宛先を指定できるツールが無い。受信者は業務システムだけが決める。

生成文への個人情報

型の制限、送信前の検査（金額・人名・連絡先・健康の語）と固定の文面。

無人の処理の暴走

既定で拒否。委託の分類を導入先が明示。同じ event では 1 回だけ。

モデルへ送るデータ

会話・本人の範囲の業務データ・添付は、導入先が選んだモデルの提供元に送られる（添付は画面に常に表示）。

約束は、テストで確かめる。
