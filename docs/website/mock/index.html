  • 人が画面を開くまで、何も起きない

AFTER ── 考えて動くシステム

  • AI 社員が変化に先に気づく
  • 関係する人にだけ、その人のチャットに届く
  • 承認はチャットのワンタップで決まる
  • 朝と夕方に、まとめが届く

Integration paths

旧いシステムにも、新しいシステムにも。

業務ロジックの書き換えは不要。ただし、何も変えずにつながるわけではありません。足すものを最初の診断で一覧にします。

足すのは「ブリッジ」

  • 業務データを読む口と、AI の提案を受ける口
  • manifest（システムの自己紹介）
  • 本人の SNS 連携（システム自身のログインで）
  • 受信者を業務システムが決める規則
  • 状態変化を同じトランザクションで event に
  • 承認の規則・定時報告（件数だけ）
1manifest を書いて検証
2hooks を実装（または別名）
3トランザクションで event
4適合性テスト 52 / 52
5AI 面の profile に登録
6業務 Web に画面と BFF

生まれたときから、AI 社員と働く

  • server-kit の上で作れば、Bridge の部分は部品が持つ
  • 書くのは業務・hooks・manifest・画面だけ
  • 見本の業務システムで、構成と書き方を確かめられる
server.mjs
const bridge = await createBridgeApp({
  manifest: { file: './bridge.manifest.yaml' },
  store, serviceToken, bffSecret,
  hooks: { employees, authenticate, isSessionLive,
           recipientsFor, approvals, proposalKinds,
           reports, piiScan },
})

コードを変えずに、外にブリッジを置く

  • ログインを外から確かめられる（OIDC / SAML）
  • 本人として呼べる API がある
  • commit 後の変化の知らせ（webhook / CDC）がある
  • 承認と書込みの API がある

FAQ

よくある質問

既存システムのコードは変えずに済みますか？

業務ロジックの書き換えは不要ですが、ブリッジ（読む口と提案の口・manifest・本人の SNS 連携・受信者の規則・event の記録など）の追加は必要です。最初の診断で、足すものと量を一覧にします。

AI が勝手に承認や支払いをしませんか？

できない作りです。AI の書込みは「提案」だけで、確定・承認・支払・金額の決定は人が業務システムで行います。プロトコルとテストで確かめています。

どのチャットで使えますか？

Slack・LINE・Microsoft Teams・WeCom・WeChat・Lark など。職員が自分のボットをつなぐ「個人ボット」は 12 種類のチャットに対応しています。email は通知だけに使います。

個人情報はどう扱いますか？

業務の変化の記録（event）と通知には ID・日付・件数だけを載せ、送る前に検査します。AI 社員の記憶にも個人情報は残しません。
